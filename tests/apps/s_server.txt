# `openssl s_server` (cargo xtask test-apps). Paired lines (SERVER || CLIENT) run the server on
# loopback (-accept 127.0.0.1:0, its port read from its ACCEPT line) against an s_client, ours
# and the reference's both ways (xtask/src/test_apps/pair.rs); what is random (session IDs,
# tickets, master keys, times) is masked. Fixtures are in tests/apps/s_server/: close.txt
# (a line, then CLOSE for -rev), get.txt and get-file.txt (HTTP requests), DER and encrypted
# copies of the reference's servercert.pem/serverkey.pem, CRLs of its CA and Root CA, an OCSP
# response for servercert.pem, and a TLS 1.3 session from a PSK handshake (for -psk_session).
# ECDSA signatures vary in length, so the servers' second certificates are Ed25519; rustyssl's
# session tickets differ in length from OpenSSL's DER when a session's contents vary, so those
# lines run with -no_ticket. -security_debug_verbose only has to succeed: rustyssl's TLS core
# makes its security checks in another order. -engine and -provider errors name the build's
# directories, which are masked.
