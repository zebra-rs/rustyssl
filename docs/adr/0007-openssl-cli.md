# ADR 0007: The `openssl` command-line tool in Rust (Phase 11)

Status: proposed (2026-10-20). The decisions marked **[user]** in section 7 are open.

## Context

Until Phase 11, the CLI is upstream's `apps/`, built from the reference's source and run on our
libraries (`cargo xtask test-apps`, and every app-driven recipe in `test-openssl-suite --all`).
Phase 11 replaces it with a Rust `openssl` binary: the same commands, options, help and error
texts, exit codes, and byte-exact output (11.1). The upstream recipes must pass with it in place
of upstream's binary (11.2).

Upstream's CLI is 56 command files plus `apps/lib` (about 59,000 lines). Almost everything it
prints comes from the library: `X509_print_ex`, `PEM_write_*`, `ERR_print_errors`, `BIO_dump`,
`ASN1_parse_dump`, `SSL_SESSION_print`, and so on. The commands themselves add option parsing
(`apps/lib/opt.c`), file and password handling (`apps/lib/apps.c`), and their own printf lines.

## 1. How the CLI reaches the library

| | (a) The public C API, like upstream | (b) The safe core crates directly | (c) Hybrid |
|---|---|---|---|
| Output, errors | come from the same exports applications use, so they're byte-exact by construction | must be rebuilt above the core: the error queue's text, every print function, PEM, config loading, providers, engines live in capi | splits the behavior between two layers |
| Runs on the reference libraries | yes: the same binary on 3.6.5's libraries isolates CLI bugs from library bugs | no | partly |
| `unsafe` | needed for the FFI calls | none | some |
| Duplication | none | large: it re-implements capi | some |
| Drop-in value | the CLI also exercises our ABI, as every C consumer does | none | partial |

**Recommended: (a).** The CLI is a C-API consumer like any other, so it calls the public API.

The `unsafe` (AGENTS.md rule 1) lives in one place:
- **`crates/rustyssl-ossl`:** thin, safe wrappers over the exported C API, including owned handles with `Drop` that call `*_free`, `BIO` reads and writes over slices, and an error-queue snapshot.
  - The `extern "C"` declarations are generated by `cargo xtask codegen` from the vendored headers, with the same prototypes `generated/signatures.rs` already asserts. Nothing is hand-typed.
  - Every `unsafe` block has a `// SAFETY:` comment. The crate links to `libcrypto`/`libssl` dynamically, never to `rustyssl-capi`.
- **`crates/rustyssl-cli`:** `#![forbid(unsafe_code)]`, the commands themselves.

Rule 1 says `unsafe` belongs only in `rustyssl-capi` and the `libs/*` shims, so this needs the rule to name `rustyssl-ossl` (**[user]**, decision 1).

## 2. Packaging

- **Crates:** `crates/rustyssl-cli` builds the binary `openssl`; `crates/rustyssl-ossl` is its bindings. Both are workspace members.
- **dist:** `cargo xtask dist` also builds the binary and installs it as `target/dist/bin/openssl`. On Linux it links `libssl.so.3` and `libcrypto.so.3` dynamically, by soname with versioned symbols, as upstream's binary does; on macOS it links by install name (`@rpath` plus the dist `lib/`). The installed libraries are what it runs on, and `RUSTYSSL_LIBDIR`/`DYLD_LIBRARY_PATH` can swap them, exactly as for upstream's binary.
- **`openssl version`:** upstream's logic. It prints `OPENSSL_VERSION_TEXT` from the headers it was built with (3.6.5's), and adds `(Library: …)` when `OpenSSL_version(OPENSSL_VERSION)` differs. On rustyssl it differs (`+rustyssl…`), so it shows both, as upstream's binary on our libraries does today.

## 3. Options, help, and errors

- **Vendoring:** `cargo xtask vendor` also copies `apps/` (the command sources, as a specification only; they aren't compiled) and `doc/man1/` into `abi/openssl-3.6/`, with the copyright kept.
- **Option tables:** `cargo xtask codegen` extracts each command's `OPTIONS` array into `crates/rustyssl-cli/src/generated/options.rs`. That covers the name, the value type (`-`, `s`, `<`, `>`, `p`, `n`, `f`, `F`, `E`, `c`, `M`, …), the help text, the `OPT_SECTION`/`OPT_PARAMETERS` markers, and the shared macro groups (`OPT_V_*`, `OPT_X_*`, `OPT_S_*`, `OPT_R_*`, `OPT_PROV_*`). The option names, value letters and help strings are upstream's observable interface, so they are generated, not typed.
- **One parser,** `cli::opt`, ports `opt.c`'s semantics:
  - unique-prefix matching is off (upstream needs exact names);
  - `--` handling, and `-help` printing `Usage: <prog> [options]` and its sections in `opt_help`'s exact layout and column widths;
  - errors use `opt_printf_stderr`'s exact texts (`%s: Unknown option or cipher`, `Use -help for summary.`, `Bad format`, value-range messages);
  - exit codes follow `opt.c` and each command.
- **Dispatch:** the command table, plus `openssl` with no arguments (the interactive prompt), `help`, `list -commands`, digest and cipher names as commands (`openssl sha256`), and the unknown-command message.
- **Unported commands fail closed** while 11.1 is in progress: they print `openssl: <cmd> is not implemented in rustyssl's CLI yet` and exit 1. They never fall back to doing something else.

## 4. Testing

**Golden tests: `test-apps` becomes three runs per command line.**
1. Upstream's binary on the reference libraries: the expectation.
2. Our binary on our libraries: must match run 1 byte for byte, with the same exit code.
3. Our binary on the reference libraries: must also match. This separates CLI bugs from library bugs.

The existing masks stay (version metadata, `file:line` in errors, thread ids), and `~` still marks lines that only need to succeed (timings).

**Corpus:**
- `tests/apps/<command>.txt`, one file per command, covering every option at least once, the error paths, and `-help`.
- The man1 examples.
- `tests/apps/commands.txt` stays as the cross-command smoke list.

**11.2:**
- `test-openssl-suite --all` gets `--cli ours`. In the recipe tree it replaces `apps/openssl` with `target/dist/bin/openssl`, because the recipes find the binary through `bldtop_file("apps", "openssl")`.
- The eligible pass rate must match upstream's binary on our libraries: 4334 of 4334 today.

**Not byte-compared:** `speed`'s numbers, interactive `s_client`/`s_server` sessions (scripted instead with `-ign_eof`/`-naccept` and fixed input), and TTY password prompts (tested with `-passin`/`-passout`).

## 5. Shared code (`rustyssl-cli/src/lib/`, ported from `apps/lib`)

`opt`, `app_libctx`/`app_provider` (the `-provider`, `-provider-path`, `-propquery` options), `app_rand` (`-rand`, `-writerand`), `apps.c`'s helpers (`load_key`, `load_pubkey`, `load_cert`, `load_certs`, `load_crl`, `load_csr`, the `bio_open_*` functions with `-` for stdin/stdout and their exact error texts, `app_passwd` with `pass:`/`env:`/`file:`/`fd:`/`stdin`, `set_cert_ex`/`set_name_ex`, `print_name`, `do_X509_sign` and friends, `parse_name`), `engine` (`-engine`), `config` (`-config`, `OPENSSL_CONF`), and `s_cb`/`s_socket` (the TLS commands' shared callbacks and sockets).

## 6. Order and split

**Fork F0 (alone, first):**
- the two crates, codegen of the bindings and option tables, and vendoring `apps/` and `man1`;
- `cli::opt`, dispatch and help, and section 5's shared helpers apart from `s_cb`/`s_socket`;
- `version`, the three-run `test-apps`, and `--cli ours` for the suite.

Everything else depends on it.

**Then in parallel**, each fork owning `src/cmd/<command>.rs` and its `tests/apps/<command>.txt`, in the plan's priority order:

| Fork | Commands |
|---|---|
| G1 | `dgst`, `enc`, `rand`, `mac`, `kdf`, `passwd`, `prime`, `errstr`, `asn1parse`, `list`, `rehash`, `info`, `nseq` |
| G2 | `genpkey`, `pkey`, `pkeyparam`, `pkeyutl`, `skeyutl`, `genrsa`, `rsa`, `rsautl`, `dsa`, `dsaparam`, `gendsa`, `ec`, `ecparam`, `dhparam`, `pkcs8` |
| G3 | `x509`, `req`, `verify`, `crl`, `crl2pkcs7`, `ca`, `spkac`, `storeutl` |
| G4 | `pkcs12`, `pkcs7`, `cms`, `smime`, `ocsp`, `ts`, `cmp` (with `cmp_mock_srv`), `sess_id` |
| G5 | `s_client`, `s_server`, `s_time`, `ciphers`, `srp`, plus `s_cb`/`s_socket` (after F0, as its own shared module) |
| G6 | `speed`, `engine`, `fipsinstall` (as on the reference with no FIPS module), `configutl` |

**Shared files:** forks don't edit `cli::opt` or `src/lib/`. A fork that needs a new shared helper adds it in its own command file and asks the parent to move it.

**11.2 last:** `--cli ours` across the whole tree once every command is ported.

## 7. Decisions for the user

1. **[user]** Approve the approach, (a): the CLI on the public C API. It needs rule 1 amended so that a new bindings crate, `rustyssl-ossl`, may hold the FFI `unsafe`. The alternative is to keep rule 1 unchanged by placing that crate under `libs/` as a shim.
2. **[user]** Vendor `apps/` (as a specification only) and `doc/man1/` into `abi/` and generate the option tables from them.
3. **[user]** When our binary becomes `target/dist/bin/openssl`, and so what `test-apps` and the recipes use by default: per command as each is ported, or only when 11.1 is complete. Until then, upstream's relinked binary stays the one users and the recipes get.
4. **[user]** The byte-exactness exclusions in section 4: timings, interactive sessions, TTY prompts.
